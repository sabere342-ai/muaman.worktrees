# MUAMAN-12: Local User Authentication, Roles & Sales-Only Access

## الهدف

تنفيذ نظام مستخدمين محلي وآمن للتطبيق بأدوار صلاحيات ثابتة (مالك، موظف، موظف مبيعات فقط) مع شاشة تسجيل دخول وشاشة إعداد أولي لإنشاء حساب المالك.

## النطاق المنفذ

- نظام مستخدمين محلي (SQLite) مع تخزين آمن لكلمات المرور (PBKDF2-HMAC-SHA256)
- ثلاثة أدوار ثابتة: `owner`, `employee`, `salesOnly`
- شاشة إعداد أولي لإنشاء المالك عند أول تشغيل
- شاشة تسجيل دخول عربية RTL
- شاشة إدارة مستخدمين للمالك فقط
- واجهة مقيدة لموظف المبيعات (شاشة المبيعات فقط + زر خروج)
- نظام صلاحيات مركزي يمنع الوصول حتى عبر المسار المباشر
- حماية آخر مالك نشط من التعطيل أو تغيير الدور
- اختبارات شاملة (191 اختبارًا، جميعها ناجحة)

## تصميم تخزين كلمة المرور

**الخوارزمية**: PBKDF2-HMAC-SHA256

**المعلمات**:
- Salt: 16 بايت عشوائي
- Iterations: 100,000
- Key length: 32 بايت

**التخزين**: `base64(salt):base64(hash)`

يتم التحقق بمقارنة ثابتة الزمن (constant-time comparison) لمنع هجمات timing.

**التبعية المضافة**: `crypto ^3.0.6` — حزمة Dart الرسمية من فريق Dart لتوفير SHA-256 المستخدم في HMAC.

## سلوك المالك

- يمتلك صلاحية كاملة على جميع الشاشات والعمليات
- الوحيد الذي يرى زر إدارة المستخدمين في شريط الأدوات
- يستطيع إنشاء وتعديل وتعطيل وتفعيل المستخدمين وإعادة تعيين كلمات المرور
- لا يمكنه تعطيل حسابه بنفسه
- لا يمكن تعطيل آخر مالك نشط أو تغيير دوره

## سلوك الموظف

- يستطيع استخدام جميع الشاشات التشغيلية (لوحة التحكم، المخزون، المبيعات، المرتجعات، المصروفات، الجرد)
- لا يرى زر إدارة المستخدمين
- إذا حاول الوصول إلى شاشة إدارة المستخدمين عبر Navigator.push، يتم منعه عبر `Permissions.hasPermission` أو ببساطة عدم توفر المسار
- الحماية مطبقة على مستوى الواجهة ومستوى التنقل

## سلوك موظف المبيعات فقط

- بعد تسجيل الدخول، تظهر له شاشة المبيعات فقط
- لا تظهر قائمة التنقل السفلية
- لا تظهر الأزرار أو الروابط لشاشات أخرى
- شريط الأدوات يعرض اسمه ودوره وزر تسجيل الخروج فقط
- زر الرجوع مغلق (`PopScope canPop: false`)
- لا يمكنه الوصول لأي شاشة أخرى بأي وسيلة
- شاشة المبيعات تسمح له بقراءة المنتجات والبحث وإتمام البيع دون صلاحيات إدارة

## حماية آخر مالك

- لا يمكن تعطيل آخر مالك نشط
- لا يمكن تغيير دور آخر مالك نشط
- لا يمكن للمالك الحالي تعطيل نفسه
- عمليات التحقق في `UserRepository.setUserActiveStatus` و `UserRepository.updateUser`
- الحماية في طبقة البيانات، وليس فقط في الواجهة

## طريقة إدارة الجلسة

- كائن `SessionState` من نوع `ChangeNotifier` يحتفظ بالمستخدم الحالي
- عند تسجيل الدخول: يتم تخزين `User` في `SessionState` وإعلام المشتركين
- عند تسجيل الخروج: يتم مسح `SessionState` والعودة إلى شاشة الدخول
- تستمع واجهة `FullAppShell` إلى تغييرات الجلسة للخروج تلقائيًا
- `AuthGate` هي نقطة الدخول التي تقرر أي شاشة تظهر بناءً على حالة المصادقة
