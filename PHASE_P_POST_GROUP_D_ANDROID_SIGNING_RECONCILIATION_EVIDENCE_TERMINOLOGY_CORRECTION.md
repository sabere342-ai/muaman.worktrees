The predecessor artifact (section I, "Secret-Handling Proof") contained
the following:

```text
PASSWORD_PRINTED = NO
PASSWORD_IN_COMMAND_LINE = NO  (DPAPI values recovered in-process; keytool received them as
                                 arguments to a trusted local process, not exposed in reports)
```

The parenthetical note itself acknowledges that recovered secret values
were supplied to the `keytool` child process as arguments during the
prior validation. This contradicts the unconditional claim
`PASSWORD_IN_COMMAND_LINE = NO`.

The defect is that:

- `PASSWORD_IN_COMMAND_LINE = NO` was stated unconditionally;
- the accompanying parenthetical disclosed that secrets were indeed
  passed as local child process arguments;
- these two statements are incompatible under any literal reading.

This is a **documentation precision issue only**. It does not invalidate
any finding about the signing implementation, credential distinction,
signing identity, keystore integrity, Gradle validation, or AAB
generation.
