## I. EMAIL CONFIRMATION VS IDENTITY LINK DISTINCTION

This is the critical governance finding of this session. Email confirmation
and identity linking are **separate operations**.

### Operation 1: Email Confirmation

```text
WHAT       = Confirming the pending Supabase Auth identity's email address
WHO        = Human owner (clicks confirmation link in email)
WHERE      = Outside the app; outside OpenCode
SERVER EFFECT = Auth identity transitions from unconfirmed to confirmed
APP EFFECT    = NONE (no local data is written; the app is not involved)
SESSION ISSUED = NO — confirmation does not produce an authenticated session
SHOP CREATED   = NO — create_shop_with_owner is not reached without a session
MEMBERSHIP CREATED = NO — same as shop
M1 COMPLETED   = NO — M1 requires a session; none is produced
M2 COMPLETED   = NO — M2 requires M1; not reached
```

### Operation 2: Identity Linking (M1+M2)

```text
WHAT       = Linking the local owner account to the cloud account
WHO        = Application (via IdentityLinker.linkExistingUser)
WHERE      = Inside the app, after a valid session is obtained
STEPS      = M1: signUp → session → createShopWithOwner (shop + membership)
             M2: _persistIdentity (cloud_uuid + cloudUuid + cloud.auth.email)
M1 REQUIRES = A valid authenticated session from signUp
M2 REQUIRES = M1 completed successfully
```

### Why Confirmation Alone Does NOT Complete the Link

```text
FACT 1: The current canonical link flow is signUp-based
        (identity_linker.dart:111 → cloud_auth_service.dart:140).
        VERIFIED from source.

FACT 2: After email confirmation, signUp for the SAME email returns
        "already registered" → cloudAccountExists fail-closed
        (identity_linker.dart:116-118 → cloud_auth_service._mapSignUpError).
        VERIFIED from code path.

FACT 3: Confirmation does not issue a session to the client.
        The signUp call returned session == null; confirmation resolves the
        identity's status but does not retroactively produce a session for
        the original signUp call. VERIFIED from Supabase Auth contract.

FACT 4: Without a session, createShopWithOwner (RPC requiring auth.uid())
        is unreachable. VERIFIED (migration 00020:28-31).

FACT 5: _persistIdentity only runs after session + shop creation.
        VERIFIED (identity_linker.dart:133-138 → 220-241).
```

### Consequence

```text
EMAIL CONFIRMATION IS NOT IDENTITY LINK COMPLETION.

CONFIRMATION MUST NOT BE FOLLOWED BY AN UNAUTHORIZED RETRY OF THE
CURRENT SIGNUP-BASED CANONICAL LINK ROUTE.

A SEPARATE OWNER DECISION IS REQUIRED AFTER CONFIRMATION TO SELECT
THE POST-CONFIRMATION LINKING ROUTE.
```
